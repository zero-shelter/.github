# Security Policy

## Reporting a vulnerability

Do not report vulnerability details through public Issues, Pull Requests, or Discussions.

### Product repositories

Report a vulnerability in a zero-shelter product through the affected public repository's **Report a vulnerability** button when Private Vulnerability Reporting is enabled.
Each public product repository is responsible for its own reporting intake and supported-version policy.

### Organization workflows

Report a vulnerability in zero-shelter organization workflows through Private Vulnerability Reporting in [`zero-shelter/.github`](https://github.com/zero-shelter/.github/security/advisories).

### Public website

Report a vulnerability in the public website through Private Vulnerability Reporting in [`zero-shelter/zero-shelter.github.io`](https://github.com/zero-shelter/zero-shelter.github.io/security/advisories).

### If private reporting is unavailable

Open a public Issue only to request a private security contact.
Do not include the vulnerability title, affected component, reproduction steps, impact, screenshots, logs, or any other technical details.

## Disclosure process

Maintainers acknowledge the report, assess scope and impact, prepare and validate a fix, then publish an advisory when disclosure is appropriate.
Security reports are handled separately from routine Issues and Project work.
