# Contributing to zero-shelter

Start with the affected repository’s contribution guide.

## Where to start

- Use [Discussions](https://github.com/zero-shelter/discussions/discussions) for questions, ideas, and open design exploration. Follow its [participation guide](https://github.com/zero-shelter/discussions/blob/main/CONTRIBUTING.md).
- Create or reference an Issue before starting a scoped change.
- Use a focused pull request for each logical change.
- Do not post secrets, personal data, internal URLs, or vulnerability details in
  public issues, pull requests, or discussions.

## Pull requests

Every pull request should identify its linked Issue and describe the change
scope, validation, documentation impact, and known risks. Follow the
repository's local instructions and pass all required checks before requesting
review.

## Commit messages

Write the commit subject, body, and Issue footer in English. Use the following
format and link the related Issue in the commit body.

```text
<type>(<scope>): <short summary>

Refs #123
```

Use `Fixes #123` only when the commit or merged pull request should close the
Issue.

## Public writing

Describe the problem, resulting behavior and checks performed. Preserve technical evidence, dates and attribution when editing older records. Separate automated or agent review from human approval. Remove unused template prompts before posting.
